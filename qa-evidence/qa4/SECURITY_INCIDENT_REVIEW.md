# QA-4 security incident review — transient public font payload

**Status: documented, operator investigation pending; exposure and persistence not established.** This is a security/process deviation involving an unexpected inbound public binary payload, not a finding that patient data was breached. This review does not assert that an incident has been conclusively contained or closed.

## Facts and chronology

During the previous QA-4 assessment, before the historical app and isolated DB were stopped (stop log recorded 2026-11-06 18:24:31 UTC), the agent queried GitHub's Contents API using `gh api` with a `--jq` metadata filter for [this public Fontsource WOFF2](https://github.com/unfoldingWord/translationCore4/blob/048646bc035b9c62ffe99fdf02b84d701b04986e/crates/tc-ui/assets/ds-rebuild/fonts/noto-sans-devanagari-devanagari-wght-normal.woff2). The response necessarily included the file's base64-encoded content in the JSON delivered to the transient `gh` process before filtering; the displayed filtered result was size 121,192 bytes and Git blob SHA-1 `33bd8312b0a31f3bbc0303d3d309f40a60054f85`. This unintentionally transferred a third-party font payload while seeking metadata. The exact prior command text, timestamp and full HTTP transcript are not recoverable here; do not reconstruct them as evidence. The API operation was an inbound response, not an intentional download into an app asset.

No deliberate base64 decode, font file write, font execution, or use of that WOFF2 in a browser or build is known. Base64 is an encoding, not encryption: receipt of encoded content still constitutes receipt of the payload; this does **not** establish that bytes were decoded or written to disk. This is distinct from the previously existing local TTF used for the historical controlled rendering tests. The public file's metadata does not establish the actual response contents by an independently computed SHA-256.

## Evidence and limits

- The prior disclosure and metadata are retained in `README.md`; the original process, its output stream, shell history, network capture, and prior browser logs are unavailable in this fresh environment. No exact response or process-memory snapshot is retained for independent review.
- A current process listing showed no `gh` or `jq` process; it does not establish prior process behavior. A limited scan of 68 retained QA-evidence text files found no WOFF2 base64 prefix `d09GMgAB`; the blob SHA occurred in the README. This is neither a full disk/log scan nor proof of absence: encoding, fragmentation, truncation, other storage, cache, memory, swap, terminal capture, platform logs and network telemetry remain unknown. No cleanup was performed.
- The request targeted a public font file and no patient record was intentionally included in the metadata operation. There is no evidence here of outbound patient content or external disclosure, but absence cannot be established without relevant audit/network logs. Whether authentication headers were used, and any related credential or request metadata exposure, cannot be determined from the retained evidence. Do not inspect secrets to resolve this.
- No known font artifact was added to the application. This follow-up did not repeat the API operation or download/decode the reference asset. Prior browser tests used synthetic data only; they do not prove what was present in any separate log.

## Non-destructive containment and operator follow-up

The transient process is no longer observed; no additional content request or destructive cleanup was undertaken. An authorized security operator should preserve available platform/session, `gh`, network proxy and GitHub audit records under normal retention and access controls; establish the operation's exact time, endpoint, authentication usage, request and response handling, and any storage/log copies without copying the payload into new logs. Correlate destinations and scope of any potentially sensitive outbound data. Assess whether policy, contractual or legal reporting thresholds apply and record a decision, owner and closure evidence. Restrict investigation to authorized metadata; do not print or rotate credentials absent an informed incident response decision. If retention policies require deletion, use the organization's approved process **after** evidence preservation and authorization. Until then classification remains a confirmed unplanned inbound public payload / policy deviation, with persistence, credential exposure and disclosure **unknown**, not a confirmed patient-data leak and not a clean bill of health.
