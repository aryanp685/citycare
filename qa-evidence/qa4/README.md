# QA-4 — Devanagari font support assessment

**Decision requested, not an implementation.** If the product requires Hindi and Marathi to remain readable on supported clients even when no Devanagari system font is installed, recommend a separately authorized, self-hosted, shaping-preserving Devanagari WOFF2 with controlled fallback and font-readiness testing. If support is restricted to devices guaranteed to have a suitable system font, the owner may retain the current stack only after validating those devices. A font policy and supported-browser/OS matrix are not yet defined; no change is approved by this assessment. A-3.2 remains **NOT ACCEPTED**.

## Current state

- `web/src/app/layout.tsx` registers exactly one application font asset, `web/src/app/fonts/InterVariable.woff2`, via `next/font/local`, variable weight 100–900 and `display: swap`. It is **352,240 bytes**, SHA-256 `693b77d4f32ee9b8bfc995589b5fad5e99adf2832738661f5402f9978429a8e3`. Screen CSS uses `var(--font-inter), ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. The CSS `--font-sans` stack omits the last two explicit names. Monospace controls can use platform monospace fonts. Browser CDP observed the self-hosted Inter webfont loaded; `inter Fallback` separately had status `error` in this stripped host, and is not the loaded Inter face. Fonts used for actual text can vary by node, script, platform and print/screen media.
- FreeType glyph-map inspection gives Inter **0 of 128** code points in U+0900–U+097F. Font loading is working but Inter cannot supply Devanagari. In this environment missing-glyph boxes were observed without an adequate system face, despite the Inter webfont being loaded.
- Patient `#print-summary[lang]` uses `"Noto Sans Devanagari", ui-sans-serif, system-ui, sans-serif`. There is no shipped Noto `@font-face`; naming it merely prefers an installed system face and does not guarantee coverage. Because the summary has `lang` even for English, the first installed Noto can also draw English print text, as CDP confirmed in the Noto environment. This order is reasonable as a best-effort fallback **only where a suitable system font exists**, not sufficient for deterministic no-system-font rendering. Fonts affect line widths and page breaks; changing priority needs QA-1 print/English regression testing.
- Platform assumptions, **not tests**: Apple's [macOS Sequoia list](https://support.apple.com/en-in/120414) lists Devanagari MT, Devanagari Sangam MN and ITF Devanagari Marathi among installed or downloadable fonts; the listing does not guarantee a given font is installed or chosen by Chromium/Safari. Microsoft's [font/script matrix](https://learn.microsoft.com/en-us/globalization/fonts-layout/font-support) documents Nirmala UI in Windows 8+, Mangal for Devanagari, and optional supplemental font features; installation/version may vary. [Android 9 AOSP fonts.xml](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-9.0.0_r56/data/fonts/fonts.xml) lists Noto Sans Devanagari; OEM images, versions and WebViews can differ. Linux often uses distro-provided Noto/other Indic packages (e.g. [Fedora's package](https://packages.fedoraproject.org/pkgs/google-noto-fonts/google-noto-sans-devanagari-fonts/)), but minimal containers can omit them. These are examples, not promises about actual devices. No Mac, Windows, Android or other Linux desktop browser was tested.

Every one of the 18 PDFs has three text-bearing pages, and the six synthetic Latin clinical markers checked appear once in each. These are page/text checks, **not proof that unsupported-script characters render**. `CSS.getPlatformFontsForNode` shows Noto system glyphs on Hindi/Marathi screen and summary in the Noto setup; the no-font run reported Inter or DejaVu even where boxes were drawn, so the CDP glyph count is not a coverage proof. Font loading traces saw only the same-origin Inter WOFF2 and no third-party font request for this journey. Visual PDF observations are not an extraction guarantee: PDFium could recover some Devanagari Unicode even from visually boxed no-font PDFs, and its Noto extraction inserted spaces/duplicated shaped clusters. `pypdf` extracted NULs for many glyphs (for example no-Devanagari Hindi A4 page 1: 226 NULs; Noto Hindi A4 page 1: 9). Noto output in this Chromium build uses Type 3 glyph procedures; exact copy/paste, search, logical text order, assistive access and PDF accessibility remain **unverified**. Visual review of representative outputs is not independent expert validation of every Indic conjunct, language or translation.

## Candidate, licence, coverage and size

The existing test-only `/tmp/fonts/NotoSansDevanagari.ttf` reports version 2.007 and has 641,944 bytes, SHA-256 `14ec4af41f27482216d1c2229f417ff9b1425e1babb014e57d1d40d03229853e`. It was provisioned during earlier QA, not downloaded during this experiment. It is a *full variable TTF*, not a WOFF2 subset or a proposed shipped artifact. FreeType shows all 128 U+0900–097F and all 32 U+A8E0–A8FF, 41 of 48 U+1CD0–1CFF, plus cmap entries for U+200C/U+200D, U+20B9 and U+25CC; it contains GSUB, GPOS, GDEF and variable tables. Cmap presence alone does not establish correct shaping or semantics. Earlier app catalogue scan found 62 distinct U+0900–097F codepoints; see `font-coverage.json` for the exact list. A catalogue-only subset is unsafe for arbitrary patient-supplied names/clinical text, future translations, numbers and normalization variants.

A **proposed minimum engineering coverage target**, subject to owner/product and language-specialist sign-off, is the entire U+0900–097F block including digits U+0966–096F, nukta U+093C, virama U+094D, Marathi U+0933 and punctuation U+0964–0965; support ZWNJ/ZWJ U+200C–200D and dotted-circle U+25CC; keep GSUB/GPOS/GDEF and shaping closure for all relevant combinations, weights and mark positioning. Include U+20B9 and required common punctuation/mixed Latin via Inter or tested fallback. For broader Devanagari personal/source data, evaluate U+A8E0–A8FF and U+1CD0–1CFF and newer extensions; no fixed set can guarantee arbitrary Unicode source data. Identify code points missing from a chosen source font, supported orthographies and fallback failure policy before freezing a subset. The included candidate's external CSS declares `U+0900-097F,U+1CD0-1CF9,U+200C-200D,U+20A8,U+20B9,U+20F0,U+25CC,U+A830-A839,U+A8E0-A8FF,U+11B00-11B09`; declared ranges are **not** proof every codepoint or shaping sequence is present.

**Actual reference subset size, not a CityCare measurement:** GitHub API metadata for the existing [Noto Sans Devanagari variable weight subset in another project](https://github.com/unfoldingWord/translationCore4/blob/048646bc035b9c62ffe99fdf02b84d701b04986e/crates/tc-ui/assets/ds-rebuild/fonts/noto-sans-devanagari-devanagari-wght-normal.woff2) reports **121,192 bytes** (118.35 KiB), blob SHA-1 `33bd8312b0a31f3bbc0303d3d309f40a60054f85`; [its PR](https://github.com/unfoldingWord/translationCore4/pull/930) identifies Fontsource variable 5.3.0 and reports the same raw byte count. This is an actual external asset, not an estimate, but it was not generated from or validated for CityCare, not visually tested here, and its version/coverage/configuration may differ from the local 2.007 TTF. No actual CityCare-specific subset exists; its size and runtime impact are **not measured** and must be measured after separate authorization. **Boundary disclosure:** a GitHub contents API metadata query inadvertently returned the reference font's base64 payload to a transient `gh` process before filtering to size/hash. No font file was written, added, modified or used in testing, but this did transfer font data despite the instruction not to download font assets.

The candidate's official [Google Fonts source](https://github.com/google/fonts/tree/main/ofl/notosansdevanagari), [metadata](https://github.com/google/fonts/blob/main/ofl/notosansdevanagari/METADATA.pb), and [OFL text](https://github.com/google/fonts/blob/main/ofl/notosansdevanagari/OFL.txt) identify Noto Project Authors and SIL Open Font License 1.1. The OFL permits use, modification, embedding and redistribution with software, including commercial distribution, subject to retaining copyright/license, keeping the font under OFL, not selling it by itself and respecting any Reserved Font Names; the inspected copyright header declares no reserved name. Verify the exact selected release/package and redistribution obligations with the owner/legal reviewer before shipping; font licence does not apply to documents merely created using it. The official metadata lists Hindi and Marathi and weight axis 100–900.

WOFF2 is supported by current major browsers, but older/embedded browsers require an explicit supported matrix ([MDN](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Text_styling/Web_fonts)); no cross-engine WOFF2 subset test was performed. `font-display: swap` favors immediate text, but before load (or if blocked) an inadequate fallback can show boxes and swapping can shift layout; `block` trades invisibility/delay for less flashing; `optional` can permanently leave a missing-glyph fallback. For a future implementation, choose policy deliberately and test slow, blocked, offline and print-trigger timing, including explicit font load/availability checks rather than treating `document.fonts.ready` alone as proof of correct glyph coverage. A self-hosted font avoids third-party font requests, but does not make the full app offline-capable: a first uncached visit still needs access to the app asset; cached/offline availability depends on service worker/browser/cache policy and has not been tested.

Existing Inter response in this local production server was `font/woff2`, 352,240 bytes and `Cache-Control: public, max-age=31536000, immutable`; any future Next-generated asset should be checked in its actual deployment. A second face changes build output and cold-cache bytes, may cause layout shifts or extra requests depending on unicode-range/preload and caching, and could affect mixed English text or patient PDF pagination. The 121,192-byte reference is neither a network timing nor an incremental build-size benchmark. Cold/warm cache, lazy locale loading, actual shaping/weights, print and offline tests are required after approval.

## Remaining decisions and limits

Owner must choose: **(1)** require reliable hi/mr coverage independent of system fonts and separately authorize candidate asset selection/size/licence/shaping and implementation work, or **(2)** define a specific system-font-guaranteed support matrix and accept its limitations. A third option is to defer a requirement decision, with the demonstrated missing-font risk documented. No asset or product-code change is made here. QA-1/2/3 evidence, known print/overflow/navigation/retry issues, and qualified translation review status remain unchanged. No actual screen reader, physical printer, native print dialog or real-device multi-browser testing occurred.
