# QA-1 synthetic headless Chromium print evidence

All content is synthetic. Patient PDFs and rasterized pages cover short/long × en/hi/mr × A4/Letter. `browser-matrix.json` records the print DOM and layout; `pdf-analysis.json` records PDFium page counts, per-page extracted character counts, marker counts, unmatched full DOM lines and the doctor raster comparison. The long fixture is inserted into a fresh isolated PostgreSQL demo DB, not injected into the DOM: 14 allergies, 14 conditions, 60 confirmed medicines, 3 draft medicines, 12 named readings, 5 lab results, and a last encounter with diagnosis and advice. The summary also includes the seeded patient identity and pre-existing data. The original summary contract shows five latest labs, one last encounter and a draft-exclusion note; it does not promise to print every historical record or arbitrary medication notes.

There are 107 uniquely checked long-fixture markers (including the encounter diagnosis and advice) in each long PDF, each exactly once. No draft medicine name appeared. Every patient page has text. All English section lines and footer lines match after whitespace normalization. Hindi and Marathi extraction does not exactly match 3–5 full DOM lines, including some footers/note/heading, due to extracted glyph order/shaping and inserted characters; the rendered pages were inspected visually, but exact Unicode extraction of those lines is **not verified**. This is an extraction/accessibility limitation, not proof that all downstream PDF readers will render or extract them properly. No qualified translation review is claimed.

The PDF pages were rasterized with PDFium at 1.2× and inspected for pagination, clipping and overlap. In these samples no unexpected blank patient page or visible clipped/overlapped content was observed; print backgrounds leave a pale screen-background rectangle below the footer on the last page. The long medication list spans pages and continues without a repeated section heading. These tests do not prove every possible record length or unbroken text is safe.

Doctor current vs patient-specific print rules removed in-memory: same count and pixel-identical PDFium rasters for each page for both sizes; each has a pre-existing text-empty second page. The doctor summary is consented; a different non-consented patient produced no summary and a 403 record API response. No doctor fix is authorized here.

Scripts document the performed procedure. `print-matrix.cjs` depends on this sandbox's separately installed Puppeteer/Chromium and pg and its disposable 3111 print app/database; it mutates that DB with synthetic rows and is not safe to repeat without first recreating the scratch DB. `analyze-pdfs.py` uses the separately installed PDFium/Pillow. These are not application dependencies. Fontconfig used an externally provisioned Noto Sans Devanagari font (`/tmp/fonts`), not a font shipped with the app. Native print preview, physical printing, other browsers and screen readers were not tested.
