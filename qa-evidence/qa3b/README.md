# QA-3B — patient landmark evidence

All observations use an already-provisioned isolated synthetic database and production builds in headless Chromium 153. No product files were changed in this iteration. The current patient-only `PatientNoticeRegion` groups the existing banner and language switcher in one localized named section; other routes receive a fragment instead.

For a controlled before/after comparison, a separate `/home/user/qa3b-baseline` copy of the application was built with the region component replaced by a fragment (all other working-tree code unchanged). Nothing in the checkout was overwritten. This reproduces the pre-QA-3B grouping, not the entire historical application. Both current and baseline were built and served with demo on and demo off; the prebuild DB URL was empty in all builds.

- `browser-on.json` / `browser-off.json`: for en/hi/mr, axe `region` before = two nodes with demo on, one with demo off; after = zero. Landmark sequence after is one localized SECTION, HEADER, NAV, MAIN, FOOTER. One note when enabled, zero when disabled; one functional, labelled/described select in both. Selection, document language and storage persisted across real reload. No patient page errors/console errors were captured. Widths 320/375/390/414/768/1280 show no document overflow for the populated fixture. Viewport screenshots provide visual context.
- Doctor `/doctor`, admin `/admin` and public `/legal/privacy` normalized rendered body HTML was identical between baseline and current for both demo modes in the tested Hindi-preference session. Comparison removes scripts, style/link elements and transient animation transform style; this is not a claim about every route or every runtime condition. No extra patient region appeared on these nonpatient routes. Root markup versus the main Git commit is not the relevant baseline because prior independently authorized work already added the language switcher.
- `print-{on,off}-{en,hi,mr}.pdf` and `pdf-analysis.json` are focused QA-1 regression checks: each long synthetic A4 PDF had 3 text-bearing pages and six selected markers exactly once. Only the print H1 is visible in print; screen heading is hidden. The QA-3A on-screen heading was one localized H1 per locale. This does not repeat the complete earlier print matrix.
- Mobile QA-2 stress uses a DOM-only 220-character synthetic unbroken medicine/reading string. At 320/375/390/414px there was no document overflow in all locales. A previously unrecorded **wider-screen limitation** appeared at 768 and 1280px for the long medication string. `long-text-comparison.json` isolates English medication vs chart and proves the same widths both with and without the patient landmark (2415/768 and 2671/1280 for medication; chart stays within viewport). It was not fixed in this QA-3B-only iteration; normal populated data fits at all six widths. This is not evidence that all possible content is safe.
- `http-e2e.cjs`: 14 focused auth/records/documents/consent HTTP checks, banner-off build. The full repository E2E suite was **not run** because it performs schema/migration operations. These checks are not a substitute for that suite.

No schema or migrations; normal login/doctor access wrote synthetic sessions/audit entries. Browser test dependencies are preexisting sandbox tools, not project dependencies. The browser uses serverless insecure flags; Noto is supplied in the QA environment only. No actual screen reader, native print preview, physical printer, other browser, or qualified translation review was used. The known patient nav keyboard-focus clipping, retry-button recovery and doctor print blank page remain outside this scope.
