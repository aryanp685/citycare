# QA-3A: patient records visible heading

Synthetic-only evidence from a previously bootstrapped, isolated local PostgreSQL database and Chromium 153 against the production build. The original populated/empty records implementation already had the localized screen H1; a forced route loading/error test found neither fallback had an H1. Records-only loading and error fallback headings were added in this iteration. The shared patient loading component was reused without modification.

- `browser-http.json`: populated heading sequence (one H1 followed by six H2s), hidden print H1, actual three-locale × six-width measurements, empty states, targeted 320px long-string overflow check, print-mode visibility, doctor headings, HTTP statuses. Screenshots are viewport captures, not full-page.
- `error-states.json`: actual database-blocked navigation and forced query failures expose the loading skeleton and records error boundary, then a retry and reload. All three languages and six viewport widths have exactly one visible translated H1 and no document overflow in both fallback states. Loading is induced with a temporary `ACCESS EXCLUSIVE` table lock, then two blocked backends are terminated to exhaust the app's retry; the lock transaction is committed before retry. No DDL, migration, or fixture row update. HTTP login and authorized/denied doctor reads normally write synthetic sessions and audit entries.
- Retry caveat: the existing “Try again” button did not recover within six seconds after this deliberately induced server-rendering error; a full reload recovered. This occurred before and after the heading change; the cause was not investigated or fixed under QA-3A.
- `print-{en,hi,mr}-A4.pdf` and `print-analysis.json`: long fixture, 3 nonempty pages each; six selected markers once per PDF. Screen H1 disappears in print; only the print H1 is visible. This is a targeted regression, not a repeat of the full QA-1 matrix.
- `http-e2e.cjs`: 14 end-to-end HTTP checks on auth, real records, empty-state content, document access and doctor consent. The repository-wide `scripts/e2e.mjs` was **not run**: it executes bootstrap/schema and migration DDL and the owner expressly prohibited those operations. The focused checks are not a substitute for that full suite.

Scripts use sandbox-only tools via `NODE_PATH=/home/user/browser-check/node_modules`, fontconfig `/tmp/fonts/fonts.conf`, and the already provisioned synthetic DB/app; no new application dependencies. Headless serverless Chromium uses `--no-sandbox --disable-web-security`, so this does not verify browser security. Noto is supplied only in this environment; native print preview, physical printing, other browsers and screen readers were not tested. Human review of translations remains outstanding. Existing QA-1 doctor blank-page and QA-2 keyboard-focus limitations remain outside this iteration.
