# Patient Health Vault — synthetic QA (2026-11-07)

The checked-in harness is hard-gated to the disposable local PostgreSQL 18.6 database at `/home/user/citycare-qa/disposable-db` on loopback port 55439. It adds synthetic document metadata for two fictional demo patients and uploads and deletes a synthetic PDF. Run only with the disposable test environment and external Playwright/Chromium dependencies; it mutates that database. Chromium runs with `--no-sandbox`, so this is not browser-security evidence.

The final run recorded 14 passing checks: pagination across 121 synthetic rows with repeated stable page reads; title search beyond the prior 100-row limit; independent quota; literal `%` and combined type filtering; two-patient ownership isolation; invalid filter rejection; UI filtering, pagination and empty state; viewport width checks at 320, 375 and 1280; encrypted upload, signed open and original bytes, cross-patient link/delete denial, deletion and blob removal; Hindi/Marathi control rendering. Screenshots contain synthetic data. The harness originally needed the correct Chromium library path and a localhost dev origin, and its first language test used a locator tied to an English heading; these harness issues were corrected before the final run.

The UI sends search text in an encoded request header rather than the URL; infrastructure capable of logging headers still requires appropriate redaction. The API also accepts a `q` query parameter for integrations. Results use offset pagination with deterministic ordering, not a snapshot: concurrent inserts or deletes may shift pages. UI is capped at 500 pages; users can narrow their filters. Upload quota checking remains non-atomic under concurrent uploads. Testing does not establish production readiness, concurrency safety, screen-reader compatibility, native-speaker acceptance or resolution of DW-P0-01/02.
